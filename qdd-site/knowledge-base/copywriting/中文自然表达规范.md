# qdd.app 中文自然表达规范

版本：2026-08-14  
适用范围：首页、国家页、专题页、FAQ、词汇表、出海专题、可编辑卡片和后续新增国家。

## 先说人话，再保留术语

页面默认使用简洁、具体、能直接行动的中文。英文只保留三类内容：

- 官方系统或机构的正式名称，例如 DS-160、EVUS、VFS。
- 域名、产品名和法律文件名。
- 视觉上确实有辨识作用的品牌短语，但必须同时给出自然中文，不让英文承担主要信息。

标题和按钮优先使用“先做什么、再看什么”的动词，例如“进入官方办理页面”“查看材料清单”“告诉我们哪里需要更正”。少用名词堆叠和逐词翻译。

## 统一替换

以下表达禁止重新出现：

| 不再使用 | 统一改为 |
|---|---|
| 每个结论都要能回到原文 | 每条说明，都附有官方出处 |
| 发现政策变化或页面错误？ | 发现政策变了，或页面写错了？ |
| 同类规则继续查 | 还想看看类似目的地？ |
| 免签也要办这些手续 | 免签入境，也要做好这些准备 |
| 中国护照去某国，从这里开始 | 持中国普通护照去某国，先看这份说明 |
| 打开官方入口 | 进入官方办理页面（若是入口页面） |
| APPLICATION DESK / OFFICIAL SOURCES 等 | 申请入口 / 官方出处 |
| VERIFIED | 已核验 |

## 语气和句式

1. 一句话只承担一个动作；把“核验、申请、入境”分开写。
2. 用“可以、需要、不能、以……为准”直接说条件，不用“在这里不需要……”等绕法。
3. 将“成功率”限定为官方整体统计；没有可比统计时写“官方未公开个人成功率”，不造数字。
4. “免签”后面必须补停留期限、入境材料和不能从事的活动；不能写成无条件入境。
5. “签证有效期”与“允许停留期”始终分开解释。
6. 论坛和社交平台内容只能作为“常见问题线索”，不得写成政策依据。

## 发布前四道检查

1. 中文编辑：去掉直译、公文腔、营销承诺和空泛抽象词。
2. 双语审校：核对官方术语、机构名、域名和中英文含义是否一致。
3. 产品文案审校：确认标题、按钮、错误状态和帮助文字能让用户马上知道下一步。
4. 构建检查：npm run build && npm run check。check.mjs 会拦截已废弃的直译表达；新增国家也必须走同一套检查。

如需新增英文品牌短语，必须在同一组件中提供清楚的中文说明，并在评审记录里说明保留原因。
