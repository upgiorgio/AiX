# qdd.app「出海目的地」扩展方案

> 版本：v1.0 · 设计日期：2026-08-14
>
> 本文只定义数据契约、页面边界和审核工作流，不改动现有 `build.mjs`、`visa-cards` 数据源。后续实现时，先增加适配层和校验器，再逐步迁移国家内容。

## 1. 要解决的问题

现有页面更适合回答“短期旅游如何入境/申请签证”。新增需求会同时涉及四类问题：

1. 哪些目的地近期更适合中国用户出海；
2. 去当地成立公司、经营或工作需要什么资格和资金；
3. 个人如何开借记卡、储蓄账户、信用卡；
4. 真实用户在申请、开户、入境和合规过程中遇到的故障。

这四类内容不能混成一张“签证攻略”。网站必须把“官方规则”“机构流程”“实践预算”“社区经验”分层呈现，并始终说明适用身份、时间范围和证据等级。

## 2. 信息分层原则

### 2.1 四个证据层级

| 层级 | 内容 | 页面标识 | 可以怎样写 |
|---|---|---|---|
| A | 政府、移民局、税务局、公司注册处、银行官方文件 | 官方规则 | “官方页面要求……” |
| B | 使领馆、签证中心、银行正式客服/产品条款 | 机构流程 | “受理机构通常会要求……” |
| C | 律师、会计师、注册代理、持牌顾问的公开说明 | 专业解读 | “专业机构建议先确认……” |
| D | X、Reddit、论坛、小红书等公开用户案例 | 社区经验 | “多名用户报告曾遇到……，不代表普遍规则” |

A/B 才能支撑“要求、资格、费用、期限、是否允许”的结论。C 只能补充实践路径；D 只用于发现问题、解释摩擦和提供核对方向，不能单独推出法律结论、成功率或最低资金。

### 2.2 政策与经验必须分开

每一条内容都应带 `evidenceLevel` 与 `claimType`：

- `policy`：法律/行政规则，必须有官方来源和适用日期；
- `process`：办理机构的流程和材料清单，必须标注机构/领区；
- `budget`：估算或实践预算，必须写假设、币种、是否含代理费；
- `experience`：用户经验，显示样本数、来源时间和“个案不代表保证”；
- `warning`：风险提醒，尽量回链官方处罚/拒绝/合规页面。

“成功率”默认不显示百分比。只有在样本定义、分母、时间、来源公开且可复现时，才能称为统计数据；否则统一改为“影响结果的因素”“社区案例信号”，不得出现“包过、稳过、内部名额”。

## 3. 统一数据契约

建议在 `knowledge-base/countries/{slug}/` 增加结构化文件，文件可为 JSON 或 YAML；现有国家正文继续由当前源文件生成，新增模块通过适配器读取。字段命名保持英文，页面文案由构建层处理。

### 3.1 国家与热门排行榜

```json
{
  "countryCode": "JP",
  "slug": "japan",
  "nameZh": "日本",
  "nameEn": "Japan",
  "coverageStatus": "partial",
  "ranking": {
    "rank": 1,
    "score": 82,
    "period": "2026-Q3",
    "methodologyId": "outbound-demand-v1",
    "signals": {
      "searchDemand": {"value": null, "source": "pending"},
      "entryAccessibility": {"value": 0, "source": "visa-facts"},
      "businessInterest": {"value": null, "source": "pending"},
      "communityQuestions": {"value": null, "source": "pending"}
    },
    "confidence": "provisional",
    "lastCalculated": "2026-08-14"
  }
}
```

排行榜不是编辑主观排序。`score` 应由公开、可复核的信号组成，并显示计算周期：搜索需求、入境可达性、商务/创业需求、社区问题量、资料完整度。不同目的应有不同榜单，例如“短期旅游热门”“创业注册热门”“远程工作/开户关注度”，不能用一个综合分掩盖差异。数据未采集时用 `null`，不能填估算数。

排行榜页面建议包含：

- 方法说明、更新时间、数据覆盖范围；
- 目的切换（旅游、留学、创业、就业、远程工作）；
- 排名、分数、信号构成、证据等级；
- “资料尚未齐全/仅有社区信号”标签；
- 进入国家详情的 CTA。

## 4. 页面与导航结构

### 4.1 新增入口

```text
/ranking/                         出海热门国家排行榜
/country/{slug}/                  国家总览（现有页面兼容）
/country/{slug}/business/         公司注册、经营与签证关系
/country/{slug}/banking/          个人账户、借记卡、储蓄账户、信用卡
/country/{slug}/troubleshooting/  常见问题与公开案例信号
/methodology/ranking/             排名方法与数据限制
/updates/                         政策变动与复核记录
```

如果某国模块还未完成，页面展示“正在核验”，而不是空白或复制别国内容；导航可以提前预留，但 `coverageStatus` 必须阻止未审核模块被当作完整建议。

### 4.2 国家详情页推荐顺序

1. **一句话结论**：当前身份/目的下能否走这条路线；
2. **三种身份切换**：短期访问者、准备创业者、已有居留者；
3. **签证与入境**：官方申请入口、材料、期限、领区差异；
4. **公司注册**：实体、外资限制、注册步骤、牌照与持续合规；
5. **个人金融**：开户资格、借记/储蓄、信用卡、税务居民和 KYC；
6. **预算与时间**：法律门槛、实践预算、假设和不确定项分开；
7. **问题诊所**：症状—可能原因—官方核对入口—升级渠道；
8. **来源与变更记录**：按模块显示证据和日期。

用户可直接深链到 `/business/` 或 `/banking/`，但所有深页都要保留“签证不等于工作权/开户不等于居留权”的提示。

## 5. 排名与热门国家的实现规则

### 5.1 建议的第一版榜单

初版只发布“数据完备且证据可追溯”的榜单，不急着覆盖所有国家：

- 短期出境/旅游热度；
- 创业注册关注度；
- 远程工作与个人开户关注度；
- 留学/长期居留（另行定义，不与旅游混排）。

每个榜单显示“统计周期、数据来源、最后计算时间、覆盖国家数、置信度”。“热门”是内容排序信号，不是安全、签证获批、收益或移民结果承诺。

### 5.2 分数的最低要求

- 至少两个独立信号源；
- 所有动态指标保留原始值、抓取日期和来源；
- 不能把 X 帖子点赞量直接当成需求量；
- 不能把社区案例数当成成功率分母；
- 指标缺失时降级为 `provisional`，不补零伪装精确；
- 榜单变化应生成更新记录，解释排名升降原因。

## 6. 内容审核与自动更新工作流

```text
官方源/机构源扫描
      ↓
结构化事实抽取（保留 URL、日期、范围）
      ↓
政策审校 + 金融/公司注册审校
      ↓
社区问题聚类（只作经验层）
      ↓
自动校验器：字段、日期、官方域名、危险词
      ↓
生成页面 + 更新记录 + 预览检查
      ↓
发布；高风险变更进入人工复核
```

建议新增以下检查规则（实现时再接入现有 `check.mjs`）：

- 所有 `policy`/`process` 结论至少有一个 HTTPS 官方来源；
- `officialApplicationUrl`、`officialRegistrationUrl`、`officialProductUrl` 必须显式存在或标记 `not_applicable`；
- 每条事实必须有 `qddVerifiedDate`/`lastVerified`；过期内容降级显示；
- `visa_required` 必须有申请入口；免签国家必须有官方入境/申报入口（如适用）；
- 公司注册页若出现资本金额，必须同时有 `officialMinimumCapital` 或“实践预算”标签和来源等级；
- 信用卡页必须出现“银行独立审核/不保证获批”；
- 发现“包过、保签、稳过、保证开户、成功率 100%”等危险词时阻断构建；
- 社区案例不得出现可识别个人资料；
- `policyEffectiveDate`、`officialUpdatedDate`、`qddVerifiedDate` 不允许合并成一个更新时间；
- 链接域名变更时生成 diff，不能静默替换。

### 复核频率

- 美国、英国、澳大利亚、加拿大、日本、韩国、新加坡、泰国：每周扫描变动；
- 公司注册、税务、银行产品：至少每月全量复核；开户政策和费率出现异常时临时复核；
- 其他国家：每月扫描、每季度全量复核；
- 任何官方公告、用户集中反馈或链接失效：立即进入人工队列。

## 7. 分批落地建议

### Phase 1：模型与样板

选日本、美国、新加坡、泰国、阿联酋五国，分别覆盖申请签证、电子签/免签、创业注册、个人银行和社区问题。先做 `/ranking/` 与一个国家详情模板，验证字段能否承载领区和身份差异。

### Phase 2：补齐已经上线国家

逐国补充公司、银行和问题诊所；每国完成 A/B 证据后再把 `coverageStatus` 从 `visa_only` 提升为 `partial` 或 `complete`。原有旅游卡片不删除，作为短期入境模块保留。

### Phase 3：排行榜与搜索入口

只发布可复核榜单；增加“按目的、预算、身份、是否需要当地居留”筛选。不要直接用一个“最值得去”排序替代用户决策。

### Phase 4：自动化更新与通知

把证据注册表、抓取快照、变更 diff 和人工审核记录纳入版本库；生成 `/updates/`，为用户提供“本周变更”和国家订阅。自动化只能提出变更，涉及签证、税务、工作权、银行资格的结论仍需人工批准。

## 8. 验收标准

- 排行榜有方法、周期、来源、置信度，不输出无依据的“热门”数字；
- 每个国家都能分别查看签证、公司、个人金融、疑难杂症；
- 公司成立不被误写成居留或工作许可；
- 法定最低资本、实践预算、生活费预留三者明确分开；
- 借记卡/储蓄账户/信用卡的资格、文件、KYC、费用和限制分别说明；
- 每个“申请/注册/开户”模块有官方入口或明确说明“不适用/需线下确认”；
- 社区经验有时间、来源和样本限制，不能伪装成统计结论；
- 页面明确显示政策生效、官方更新、本站核验三个日期；
- 任何国家资料不完整时，用户能看到覆盖状态和缺口；
- 构建检查能阻断缺来源、过期、危险承诺词和敏感个人数据。
